NetSec Visual Analyzer

A React and TypeScript dashboard for DNS security analysis, side-by-side domain comparison, threat-intel review, and audit-history tracking. The app uses Vite, TanStack Router, React Query, Blink UI, and a custom DNS / threat intelligence pipeline.

Overview

The project is a single-page application that helps analysts inspect the security posture of a domain, compare two domains, review threat-intelligence indicators, and inspect previous scans. The main app entrypoint wires together authentication, query caching, routing, and the Blink UI theme.

Primary goals
  • Analyze DNS posture for a domain in real time.
  • Compare two domains and score their security controls.
  • Inspect OpenPhish-based threat intel and domain risk signals.
  • Persist and review local audit history.
Core stack
  • Vite, React, and TypeScript.
  • TanStack Router and TanStack Query.
  • Tailwind CSS and Blink UI components.
  • React Three Fiber for the 3D globe visualization.

Application Flow

  1. The browser loads src/main.tsx, which configures Query, Blink auth, and the UI provider.
  2. src/App.tsx mounts the TanStack router and routes everything through DashboardLayout.
  3. The user visits one of four route-level pages: dashboard, compare, threats, or history.
  4. DNS and threat-intel requests are issued from the page layer using helper functions in src/lib.
  5. Results are rendered in Blink UI cards, tables, charts, and the 3D globe, then audit events are stored locally.
The app is entirely client-side. Audit history is persisted in LocalStorage under the key netsec.audit.history.v1.

Routes and Screens

Route Page Behavior
/ DashboardPage Runs a DNS security scan for one domain and presents score, findings, charts, and the globe view.
/compare ComparePage Runs two security analyses and compares scores, findings, and record-level results side by side.
/threats ThreatsPage Loads OpenPhish feed data, summarizes threat volume, and performs domain-level threat lookups.
/history HistoryPage Shows scan history with timestamps, scores, status, search, refresh, and clear controls.

Key Modules

src/lib/dns.ts

Resolves DNS records through Cloudflare DNS-over-HTTPS, evaluates SPF, DMARC, and DNSSEC, and returns a normalized analysis object with a 0-100 score and findings list.

src/lib/threatIntel.ts

Pulls OpenPhish feed data, classifies items, estimates confidence, derives RDAP metadata, and builds a richer domain threat profile used by the threat intelligence page.

src/lib/history.ts

Stores recent scan and comparison events in LocalStorage, de-duplicates recent duplicates, and caps the stored history at 100 records.

src/components/NetworkGlobe.tsx

Renders a rotating 3D sphere with animated points and stars using React Three Fiber and Drei.

Important UI Behavior

  • The dashboard defaults to scanning google.com until the user submits another domain.
  • Comparison mode refuses empty or identical domains and records the comparison in audit history.
  • Threat lookups fall back to a static sample snapshot if the live feed is unavailable.
  • The layout shows a sign-in or sign-out control depending on Blink authentication state.
  • Toasts are used for validation errors and scan failures.

Dependencies Worth Knowing

  • @blinkdotnew/ui and @blinkdotnew/react provide the design system and auth integration.
  • @tanstack/react-router handles routing and nested layout composition.
  • @tanstack/react-query provides data fetching, caching, and refetching.

  • lucide-react supplies iconography throughout the dashboard.

Notes and Constraints

  • The DNS and threat-intel features depend on network access.
  • The app expects a Blink project ID in VITE_BLINK_PROJECT_ID for auth features.
  • Audit history only persists in the current browser profile because it is LocalStorage-backed.
  • Shell.tsx and src/layouts/shared-app-layout.tsx are present as layout utilities, but the active app flow currently uses DashboardLayout.
